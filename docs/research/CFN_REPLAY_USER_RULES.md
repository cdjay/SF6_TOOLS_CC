# 录像分析自定义规则

Status: `DESIGN`。已同步本机的实验候选，最新配置筛选修改尚待实机验证。本功能只改变已有证据的分类建议与问题选择，不执行游戏控制。

后续目标改为[独立事实与可切换分析方案](CFN_REPLAY_FACT_RULE_DESIGN.md)。下文仍描述已实现候选，
不表示已支持任意事件序列、专题开关或完整系统条件编辑。

## 使用方式

打开 `tools/cfn_replay_capture/rule_editor/index.html`，无需启动服务、联网或安装网页依赖。
正式独立预览包将网页放在 `reframework/CFNRuleEditor/index.html`。

1. 点击“新建规则”，或“从系统分类创建”。后者保留系统分类作为一个条件，再按需增删条件。
2. 选择分析受伤段还是防御段，填写问题描述及P1～P3。组合“全部满足／任一满足／不满足”。
3. 数值可以和常数比较，也能和另一个数值字段比较。支持闭区间、存在／缺失和原始标记检查。
4. 左侧顺序就是优先顺序。同一种记录只采用第一条启用且满足的自定义规则，没有命中时保留系统结果。
5. “条件试算”输入一组假定的证据检查结果，不读取真实录像；未勾选“有记录”就是缺失。
6. “配置文本”允许直接编辑同一份JSON，供熟悉配置的用户与Codex使用。错误文本不覆盖有效草稿。
7. “保存到游戏”需要浏览器支持文件夹授权。用户选择游戏的 `reframework` 文件夹后，只写入其
   `data/cfn-replay-rules.json`；覆盖前再次确认，不修改任何Lua、DLL、录像或其他文件。授权取消不写入。
8. 不支持文件夹授权的浏览器可以“导出配置”。实际规则文件位置仍为游戏 `reframework/data/cfn-replay-rules.json`。
9. 安装支持此功能的新Lua后，修改配置不需要Reset或重录：暂停当前录像并停止定位，点击“更新规则”，或开启“自动读取规则”。
   只重新判断已载入的事实快照，不重建事件；首次读取旧记录时才建立快照。每次判断使用冻结的配置副本。

网页草稿只保存在浏览器本地，导出不表示已在游戏应用。用户自定义文件不作为产品默认配置打包。
没有用户文件时沿用系统规则。文件无效时显示提示并退回系统规则，保留伤害账本和录像。

## 可配置范围

运行侧 `rule_config.lua` 是字段、类型、界限与格式的权威。网页目录由该文件导出生成，不能独立添加另一个字段解释表。

- 294个字段：受伤/防御段、发生帧、实际伤害、段长度、关联硬直差、收招窗口、出招间隔和已有分类事实。
- 分析对象及对手：发生帧、前一连续帧的全部51个已采集玩家字段；另含血量/斗气/能量百分比和相对朝向的前/后/下输入。
- 玩家当前版本角色编号、经典/现代模式；全局当前与前一帧的17个已采集时钟/显示字段。
- 系统参数：起身后抢招范围1～30帧（默认8）；防御后抢招范围1～30帧（默认15）；
  防御后观察范围1～120帧（默认30，不包含终点）；原生硬直差绝对值初筛1～120（默认4）。
- 自定义描述、P1～P3、顺序、启用/停用；防御规则可保持、加入或排除“机会待核对”筛选。

范围不是“所有格斗知识”。未采集的碰撞箱覆盖、精确攻击距离、角色招式语义、拆投机会、确认窗口等不能凭配置生成。
原始动作编号只属于本游戏版本；系统不提供跨版本动作名称映射，不形成AC/BCM之外的语义来源。
原始坐标、动作进度、资源整数及标记均明确列为原值；百分比与横向间距使用独立归一字段。
原始显示格可以作为用户条件，但不等于通过同步检查的新格。未经关联的硬直差不会填入 `native_advantage`。

受伤条件的发生帧指该受伤段第一笔掉血；防御条件指该防御段起点。资源/输入/动作字段取该帧及其前一连续帧，
不是整段任意时刻。段伤害、持续长度、关联硬直差及后续行动则在段分析结束后提供。
不支持用户表达任意时间序列查询或执行Lua/JavaScript，这需要后续单独的有界序列规则设计。

## 证据与优先级

- 缺帧、流程变化或缺字段不填0。普通比较得“未知”，未知取反仍为未知；只有显式“没有记录”才匹配缺失。
- 可配置P1是用户的回看优先级，不代表已证明因果；自定义分类统一保留 `inferred`，并记录命中规则编号及配置名。
- P0只能来自既有人工确认文档及证据校验，自定义条件无权生成。人工确认层在自定义层之后执行。
- 硬直差正负归属、招式发生帧、实际距离未证明时，不会因配置得出官方“必然确反”结论。
- `include_system=false`时，问题列表与级别计数仅含命中的启用规则；独立人工确认不绕过该限制。
  “全部防御”仍列全部事实，“机会待核对”同样受配置选择限制。缺省或true保留系统分类行为。
  不将系统状态解释或连续伤害合并逻辑开放为任意配置。
- 不能删除掉血记录或篡改伤害总量；防御机会排除只影响筛选，不删除防御段。
- 不改变录像身份/版本/同局/暂停守卫、实际回看帧、输入控制、采样钩子或自动播放速度。

## 接口与限制

配置格式 `sf6cc.replay-rules.v1`，绑定构建 `20004000`。顶层：`schema, build, name, settings, rules`，可选布尔`include_system`。
规则：`id, title, enabled, scope, priority, when`，防御可附 `opportunity`。
条件节点：`all:[...]`、`any:[...]`、`not:{...}`，或 `{field,op,value}` / `{field,op,value_field}`。
存在性判断不带比较值；区间为两端均包含。字段比较仅支持两个数值字段的等于、不等于、大小比较。
每条描述最多180个UTF-8字节；最多100条规则、2000个节点、每组32项、深度6；网页导入文件上限1MiB。
Lua运行侧在JSON解析后验证节点和类型，不承诺在REFramework解析器之前拦截超大文件。

`rule_context.lua`只接收已保存标量和完成的事件；复用damage_rules的状态与朝向判断。
`analysis.lua`在准备阶段读取/冻结配置，结束阶段先套自定义建议，再做人工确认及统计。
后续“更新规则”走独立事实快照求值路径，仅更新分类与分类统计；详见[工作台](CFN_REPLAY_WORKBENCH.md)。
不自动扫描每一帧产生新事件，所以没有掉血、也没有普通防御记录的任意动作不会仅凭规则生成问题。

## 验证

`node tools/cfn_replay_capture/build_rule_editor.mjs --check`检查目录与Lua权威一致。
`tools/test_cfn_rule_config.lua`、`tools/test_cfn_rule_context.lua`及`rule_editor.test.mjs`检查严格格式、三值逻辑、上下限和网页/Lua一致性。
`test_cfn_replay_analysis.lua`覆盖配置快照、重新读取、错误回退、P0拒绝、伤害不变及无游戏输入。
网页通过浏览器验证创建/复制/排序、编辑条件、数值输入、试算、文本错误拒绝及导出，并检查桌面和390px窄屏布局。
“保存到游戏”的授权与写入流程使用模拟文件夹测试，不宣称已在用户游戏目录应用。
初版增加2个自有Lua模块及5个静态网页文件；工作台后续增加事实求值、导出模块及3个网页文件，
当前闭包32个Lua、58个载荷文件；没有新增DLL或外部依赖。
