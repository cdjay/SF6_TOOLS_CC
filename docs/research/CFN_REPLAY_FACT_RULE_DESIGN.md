# 录像复盘：事实与可切换分析方案

Status: `DESIGN`。按用户提出的分层记录目标设计；不表示已实现或同步。
当前规则候选仍只对已有受伤、防御段求值，默认配置没有展开系统判断条件。
参见[当前候选限制](CFN_REPLAY_USER_RULES.md)和[领域用语](../../CONTEXT.md)。

## 分层

采集记录 -> 观测及派生事实 -> 分析规则 -> 发现与专题列表。
统计直接消费事实；改变规则、专题或筛选不改变伤害账本及统计基数。
事实独立于受伤：没有掉血的防御、跳跃、出招、移动及资源变化也可以成为分析起点。

事实候选包括：受伤与接触、防御、资源、空间位置、行动过程、输入、局与时钟。
原始位置与双方间距不等于招式可命中距离；没有舞台边界证据不推定距版边距离。
Action编号绑定游戏版本；动作名称、出招路线和招式关系必须复用既有AC/BCM语义权威。
命中标记可作证据，未接触、主动消耗、资源恢复等派生事实须分别核对算法与覆盖范围。

每个事实保留录像身份、版本、局、玩家、开始/结束帧、证据来源和完整性。
缺失读数与未发生事件不能混同；没有连续记录时不能证明一段时间内未出招。
录像帧与行动推进帧、停顿分开，不将录像帧差直接当作招式发生帧。

## 规则

条件需支持事件锚点、前后有界时间范围、顺序、持续、存在及完整范围内的未发生。
例如以防御结束为锚点，核对关联硬直差和玩家归属，再观察后续行动与接触结果。
时间窗口满足而攻击范围未知时，仅列为机会待核对，不能断言漏确反。
对空与差合规则同样区分可见动作事实和应对机会推测。
缺帧、换局、流程切换终止连续性，不跨边界串联；限制规则数量、窗口和计算量。

同一事件可以命中多个专题。按事件和关注对象聚合发现，保留各条命中理由；
不得因专题重复而重复累计伤害。不能沿用当前自定义分类的全局首次命中即停止作为全部发现模型。
证据状态与P级别分离；沿用当前P0人工确认限制，规则本身不授予人工确认。

## 方案与开关

一个分析方案包含可见的规则条件、参数、版本、专题及启用状态；用户和Codex操作同一种声明式配置。
内置方案应完整展示实际条件、顺序或冲突处理，不只提供“系统原分类等于某分类”。
内置方案保留为参考，可复制修改；允许加载不同方案并启停确反、对空、差合等专题。
关闭专题仅停止该类发现的生成或展示，不停用事实采集，不删除已保存事实。
配置变化后基于已有事实重新分析，不在一次运行中混用两版配置；新规则缺必要事实时明确不可用。
加载的配置不能执行任意代码、增加游戏钩子或改变控制许可。

## 实施顺序及验收

1. 固定现有事实和分类样例，公开完整系统条件，保持默认结果与伤害账本一致。
2. 独立事实目录及有界事件查询，增加没有受伤的事件入口；每种事实单独验证。
3. 在网页中组织方案与专题，支持规则复制、修改、开关和命中证据预览。
4. 优先接入受伤、防御与确反待核对，再按证据能力接入对空、差合和资源专题。

必须验证：默认结果一致；方案切换不影响事实；重复专题不重复计伤；连续性断裂时未发生条件为未知；
多规则命中可解释；同局/身份守卫不放宽；缺必要证据的规则不伪装为已支持。
