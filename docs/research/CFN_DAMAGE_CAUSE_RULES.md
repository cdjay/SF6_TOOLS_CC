# CFN受伤原因归纳规则

Status: `DESIGN` / isolated offline experiment. Not production authority.

## 本轮边界

目标是不设伤害门槛，解释每段交手为什么造成损失，而不是输出一张原始掉血表。实现位于 `tools/cfn_replay_capture/damage_causes.mjs`，依赖既有事件、伤害分组、状态枚举和共用的帧数表新格检查。没有改动游戏Lua、钩子、采集格式、控制按钮、定位流程或生产动作语义。

当前支持采集版本20004000。仅解释已保存区间；不把 `left_replay` 改成完成，也不自动兼容没有CFN身份的训练场录像。

## 分层

1. **伤害账本**：所有正向掉血都保留。每个掉血观察必须归入且仅归入一个复盘分组，逐局逐玩家合计必须与事件读取一致。
2. **关联过程**：复用双方原生连击计数、累计伤害和连续时钟。分组不是已经证明的最优连招或所有首击。
3. **状态事实**：受击前后状态、新出现的康标记、朝向与输入、攻击序列、真实前进的帧数表格子、之前的防御或起身状态。最多回溯600条连续同流程记录，不越缺帧或换局。
4. **原因规则**：按优先级返回规则编号、中文标题、解释、复盘重点、证据等级。未知原因必须有明确的缺失说明，不能强行生成判断。
5. **人工核验**：与自动结果分开存储。必须核对录像ID、版本、双方角色及操作模式、局数、帧号、受伤方和首笔伤害。禁止按相似输入或角色关联录像。

这不是新的角色语义解释器。不将Action编号映射到招式、不凭伤害反推LP/MP/投、不自建取消路线。未来具体招式、绿冲取消或最优后续必须通过当前版本统一语义来源接入。

## 归类规则

| 规则 | 必要证据 | 中文解释的边界 |
|---|---|---|
| 防御掉血 | 当帧防御状态、新防御标记、连击数0 | 防住但掉血，不自动算防守失误，也不只凭斗气读数判断燃尽 |
| 抓取 | 受伤方HOLD、对手CATCH及对应伤害来源 | 出招后被抓与蓝防时被抓分开；不能单凭状态区分投和当身反制 |
| 起身受击 | GETUP直接转受击 | 起身被压中，不猜测输入的招式有没有成功发动 |
| 起身抢招被打断 | 起身后8帧内出招且新增普通康 | 描述起身后抢招的过程，不宣称8帧是游戏硬性规则 |
| 挥空惩罚候选 | 出招起点可见、判定新格、未见对手掉血/防御/蓝防、受击前新格8或13、新确反康 | 规则推定；未排除攻击物等特殊接触，不能自动等同距离陷阱 |
| 出招被确反康 | 攻击状态、新确反康 | 保留惩罚结果；若前一类不足，不猜防御后确反或挥空 |
| 空中出招被打断 | 攻击状态、空中位置、新普通康 | 双方高度不是攻击物来源证明 |
| 防御后抢招被打断 | 最近15帧内防御结束、攻击状态、新普通康 | 15帧是归纳上下文范围，不代表实际帧差；不套用陈旧硬直差 |
| 出招被普通康 | 攻击状态、新普通康 | 不把普通康误当确反，也不自动断言当时一定能防住 |
| 既有受击后续 | 掉血前已DAMAGE/HOLD | 回溯最初进入状态的时点，避免每段连招都算新失误 |
| 换边期间受击 | 朝向改变、对手空中、未防住 | 规则推定；不能用受击后的朝向解释之前输入 |
| 防御松开候选 | 前一状态DEF、转DAMAGE、受击前后都无后方向 | 需复核输入与判定先后，不只看旧防御动画 |
| 蹲防未挡住空中进攻 | 下后方向、对手空中、DEF转DAMAGE | 疑似需要站防，缺命中属性时不认定中段 |
| 冲刺被截停 | 受击前DASH | 状态事实，不猜绿冲/普通冲刺具体种类 |
| 前走受击 | 移动状态、按当前朝向为前输入 | 规则推定，不把1000伤害归为投 |
| 未知 | 必需状态、来源或条件不足 | 保留损失并说明缺证据 |

CFN输入使用现场已读出的 `FBattleInput` 常量：上1、下2、左4、右8；以每帧朝向解释前后。不得复用方向约定不同的训练 `RawInputCodec`。证据见既有 `audit-output/cfn-replay-20260919/DIRECTION-EVIDENCE.md`；这里只在CFN实验内使用，不修改生产训练编码。

帧数表新格判定抽至 `meter_evidence.mjs`，供原有机会分析与新原因分析共用。停留的绿色/蓝色不能证明当前状态，时钟不匹配、游标未前进或重置均不作为新格。

## 伤害分组修正

上一版53组过度拆分：防御削血可能保留在累计伤害中；KO的最后一击可能超过剩余血量。本轮只在原生计数递增且伤害增量一致的条件下支持前者；后者要求血量确实归零且差额来自最后一笔原生伤害。统计始终使用实际掉血，不把过量伤害计入损失。非KO的不匹配继续拆开，不能盲目合并。

受击前已有长时间反应时，另外记录 `reaction_start` 和之前防御掉血的位置。这两个时点可以早于第一笔连击掉血。例如首局2431的后续连击实际要从2224防御掉血、2250转入受击看起。没有证据时不硬叫墙撞或眩晕。

## 结果契约

`sf6cc.cfn-damage-causes.experimental.v1`：

- `rules_version`：规则版本。
- `items[]`：局数、第一笔与最后一笔伤害帧、受伤方、实际总伤害、掉血次数、原账本条目编号。
- `classification`：稳定规则编号、标题、解释、检查重点、等级 `observed/inferred/unknown`。`mistake=null`，过程事实不自动等同失误。
- `facts`：触发规则的原始状态与时点，供审核和回归。
- `human_review`：独立人工结论或null，不改变自动分类。
- `locate`：CFN编号、版本、零基局数、回看帧；消费端必须检查录像身份、当前局、暂停状态及实机可跳转上下界，不自动跨局。
- `followup`：本轮未评估命中后续；缺少取消路线、资源、距离与时机的证据时，不标记漏绿冲或断连失误。

与当前Lua定位接口解耦。还未接入游戏面板，不会因为生成报告而发送按键。

## 验证与复现

```powershell
node --test tools/cfn_replay_capture/*.test.mjs
node tools/cfn_replay_capture/damage_causes.mjs <采集记录.json> audit-output/<新名称> docs/research/CFN_REPLAY_REVIEWED_CASES.json
```

第三个参数可省略，程序仍独立完成自动分类，不依赖这场录像的人工标注。新录像不得使用旧人工文件；不匹配会报错。

F978A6QHF、032052记录的112次掉血归入38段复盘，各局双方合计不变。8段附用户实测结论，其余按规则解释过程。所有条目均有过程分类，但不等于38次原因已全部证实，更不等于38次失误。

本轮共98项Node测试通过。新增21项原因测试，覆盖不同朝向、持久标记、抓取和蓝防区别、起身、防御、前走、空中、挥空证据不足、缺帧、帧数表停留、同帧流程变化、分组重置、延迟掉血的前置防御追溯及人工身份校验。分组另新增2项，原KO回归改为验证只合并真实最后一击且不多计伤害。原机会检测测试保留，旧原生硬直差报告逐字段对照完全不变。未删除任何生产永久回归。
